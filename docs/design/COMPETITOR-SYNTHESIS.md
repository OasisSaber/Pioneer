# 竞品前端设计语言深度解构与融合 (Competitor Design Synthesis)
> **对标产品**：Claude Code Desktop · Codex (OpenAI) · Opencode · Zcode
> **融合目标**：为 **Wonderwall-Pi Agent** 提炼兼具「终端极客骨架」与「Apple 极简克制」的全新数字人/任务助理设计范式。

## 1. 四大竞品前端设计语言解构

### 1.1 Claude Code Desktop：对话与 Diff 审阅的克制范式
- **优势汲取**：
  - **优雅的审批与 Diff**：将文件修改转化为极具可读性的 inline patch，操作只需快捷键确认。
  - **弱侵入式上下文提示**：使用柔和的次级灰色展示 token 消耗与模型耗时。
- **弊端规避**：缺少全景工作区视角，打开即陷入黑盒对话，用户无法感知资产全貌。

### 1.2 OpenAI Codex：结构化方案与检查点
- **优势汲取**：
  - **Plan Mode 意图确认**：在执行多步任务前生成结构化清单。
  - **Checkpoints 状态恢复**：关键节点允许一键回滚。
- **弊端规避**：Plan 偏向技术实现细节（代码级别），而非面向普通用户的意图理解核对；界面偏工程师工具。

### 1.3 Opencode：纯粹 Monospace 与零阴影美学
- **优势汲取**：
  - **极致扁平与 4px 网格**：不使用任何投影或极光渐变，靠 `#1D1D1F` 墨色、`#E0DEDE` 发丝线与字重建立清晰层级。
  - **终端原生交互**：`$` 提示符、全圆角胶囊（Pill）、`copy` 徽标。
- **弊端规避**：全 mono 字体在长篇中文阅读时容易产生视觉疲劳。

### 1.4 Zcode：工作区管理与多模型调度
- **优势汲取**：
  - **工作区资产感知**：对本地目录的扫描与活动时间线管理。
  - **多模型无缝切换**：灵活接入本地小模型与远端 API。
- **弊端规避**：存在较多仪表盘式陈列（图表、大屏、雷达图），违背数媒克制美学。

## 2. Wonderwall-Pi Agent 的融合提炼方案

Wonderwall-Pi Agent 不做上述任何一款的简单模仿，而是提炼其长处，重塑为三大专属特征：

1. **排版双轨制 (Dual-Font Hierarchy)**：
   - 界面骨架、状态元数据、终端指令行采用 **SF Mono / Sarasa Mono**；
   - 标题与长文正文采用 **SF Pro / PingFang SC**，兼顾极客质感与中文阅读舒适度。
2. **意图卡 vs 方案计划**：
   - 融合 Codex 的结构化检查点与 Claude 的自然语言对话，首创「**意图核对卡 (Intent Card)**」——执行前先核对「我理解得对不对」，而非扔出一堆技术参数。
3. **克制化适配轻提示 (Light-Hint)**：
   - 借鉴 Opencode 的单行终端与 Claude 的渐进披露，模型病理自适应策略以「底部单行叙事短句」呈现（如：*“Qwen3 在大目录易早停，已自动挂载深度遍历策略”*），点击才展开技术 Profile。
