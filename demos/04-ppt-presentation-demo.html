02 · BACKGROUND
WHY · 现有 Agent 三大交互困境选题背景与痛点
核心诊断
现有 Agent 交互
存在三大困境
当前大模型智能体技术飞速发展，但人机交互范式极其滞后。市面产品多局限于客服式聊天框，后台盲跑缺乏透明度，配置深埋于代码与终端中。数媒专业亟需重构一套专业、优雅、高可控的 Agent 桌面交互体系。
[1] 交互模式僵化单一市面产品千篇一律为“左侧历史会话 + 中间气泡列表 + 右侧文件预览”，把 Agent 当客服聊天，无法满足复杂工程工作流。
[2] 状态黑盒与失控感终端代码日志滚不到底，Agent“盲跑狂奔”，用户看不懂、不敢信、无法介入，缺乏关键安全确认闸门。
[3] 功能隐藏与门槛过高插件工具、技能配置、参数深埋在代码文件和终端命令行中，普通用户极难驾驭，能力无法直观触达。

教师提问方向 核心回答要点
1. 为什么选这个题？ 现有商业 Agent 界面高度同质化（全是一成不变的聊天框），状态不可控，配置深埋于代码；数媒专业应探索更专业、更可控的人机协同桌面交互范式。
2. 系统主要做什么？ 面向本地工作区的任务助理：上层提供 Jellyfin 海报墙与 Premiere Pro 模块化工作区，底层基于 Pi 极简底盘驱动文件与任务自动化。
3. 最核心的创新与自主工作量？ 前端“一切皆 UI”交互体系（Jellyfin 资产海报墙 + PR 可停靠面板） + 意图核对卡人机协同机制 + 前后端全链路事件驱动管道。
4. 用什么技术实现？ React + TypeScript + 可停靠面板系统（前端） ⟷ WebSocket/SSE 事件流 ⟷ Pi-Agent 极简微内核调度底座与模块化插件（后端）。
5. 和市面工具有何特色/差异？ 突破了传统 Agent 的三栏对话框死板形态；让用户能够像在 PR 中一样自由拼装面板；把项目资产渲染成影视库海报墙，直观可视。
6. 最终验收交付什么？ 可运行桌面交互系统原型 + 前端高保真设计规范 + 极简插件库 + 演示视频 + 完整源码 + 毕业论文。
7. 如果时间不够怎么删减？ P0 核心（海报墙 + PR 预设工作区 + 意图卡）坚决保底；插件功能库采取渐进式开发，时间紧张时仅保留最基础的本地文件原子插件即可，架构依然完整。
